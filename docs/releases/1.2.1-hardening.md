# 1.2.1 hardening candidate — 2026-11-21

Delta incident baseline is chart/image 1.2.0-rc2. Keep production paused at zero replicas until staging acceptance passes.

This candidate builds on c593972: status-only/bookmark filtering, generation-aware conditions and no-op patches, tunnel work coalescing, shared route inventory, Lease single writer, and unchanged-configuration write suppression.

Additional fixes: contain exceptions thrown while recording failures and supervise election-task faults; preserve shutdown/leadership cancellation; evaluate webhook health before inventory readiness; cooldown on 5xx, network errors and request timeouts as well as 429. Honor Retry-After delta/date and legacy X-RateLimit-Reset Unix timestamp. Backoff starts at 5 seconds, doubles to 300 seconds, with 0–4999 ms jitter. Header deadlines may exceed the fallback cap. Success resets the failure count. Requests have one transport attempt: no automatic mutation replay. Subsequent periodic or meaningful-event attempts pass through the same cooldown. There is no terminal retry count across ongoing controller cycles; this intentionally permits recovery after outages without changing resources.

GET /metrics/cloudflare on the existing HTTP service returns JSON counters (attempts, rateLimits, transientFailures), queueDepth, retryAt and lastSuccessfulReconciliation. It is diagnostic JSON, not Prometheus exposition. No new public ingress or ServiceMonitor is installed. Counters reset on process restart. Last success describes full inventory/route completion, not necessarily every security-policy operation.

## Staging and production gates

Use the exact immutable candidate chart and image. Retain namespace/security policies, startup protection, CreateUpdateOnly and both zero deletion limits. Apply scoped Lease RBAC from the chart. Start staging with one replica; verify event burst coalescing, stable resourceVersion for identical failures, spec/deletion handling, 429 cooldown and recovery, webhook availability and external-dns health. Then test two replicas and leader failover: only the holder may reconcile, both webhook listeners must be ready. Observe request and restart counts for at least five minutes after cooldown. A shared process gate does not coordinate account budgets with external-dns or another cluster; token/account sharing remains unverified without approved configuration access.

After staging acceptance, restore Delta through GitOps at one replica, verify all 22 resources and sampled traffic, then optionally two. Keep failurePolicy Ignore until webhook stability is established by operational review. Do not restart tunnel, ingress or application workloads. Roll back by setting replicas to zero; do not restore active rc2 workers. Preserve existing routes and ownership state. No live cluster or Cloudflare mutations were performed in preparing this release.

Remaining operational acceptance tests include injected Kubernetes API/status failure and leader-loss during in-flight Cloudflare operations. Unit coverage is not a substitute for these staging checks. Modern combined Cloudflare Ratelimit policy header parsing and account-wide budget reservation are not implemented; Retry-After remains authoritative when present.

Queue resource bursts exceeding 256 distinct keys collapse to one full pass; meaningful events are not discarded. Logical queue depth counts that full pass as one item.
