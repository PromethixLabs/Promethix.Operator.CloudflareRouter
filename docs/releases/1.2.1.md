# 1.2.1 reconciliation request fixes

## Changes

- Ignore status, resourceVersion and managedFields-only TunnelPublicHostname watch updates. Spec, labels, annotations, owner references, finalizers and deletion changes still enqueue reconciliation.
- Coalesce watch changes into full tunnel passes with a two-second batching window. Each pass reads route inventory once for all desired hostnames. Before a configuration write, fetch fresh inventory to preserve external routes. Namespace and ingress dependencies are revalidated by periodic full passes.
- Skip identical status patches, preserve condition lastTransitionTime when Status is unchanged, preserve completed security-policy conditions during route status updates, and use resourceVersion preconditions with conflict rereads. Existing finalizer no-op checks remain active.
- Serialize Cloudflare route and security-policy HTTP requests through a shared cooldown. HTTP 429 sets the next permitted request time to at least Retry-After (delta or HTTP date), with exponential fallback and jitter. Cancellation interrupts the cooldown on leadership loss. Requests have a 20-second transport timeout.
- Run reconciliation only while holding the Kubernetes Lease named `<ownershipConfigMapName>-leader` in the ownership ConfigMap namespace. Lease duration is 60 seconds, renewal deadline 20 seconds, retry period five seconds. Cancel the worker on lease loss. Both replicas continue serving admission requests.
- Fix a queue timeout that left an orphaned channel reader and could silently consume a later watch event.
- Avoid Cloudflare PUT when the rebuilt effective configuration matches current configuration. Existing ownership, startup protection and deletion limits remain enforced.

## Rollout checks

1. Record current image digests, chart values, resource conditions and a bounded log sample. Retain replicaCount=2, security policies, namespace enforcement, CreateUpdateOnly, startup protection and zero deletion limits.
2. Publish and select the immutable 1.2.1 alpha/RC chart and image produced from this change. Validate in staging first. Do not overwrite 1.2.0 or its RC tags.
3. The chart grants creation of coordination.k8s.io Leases and get/update only for the named leader Lease in the existing ownership namespace. Cloudflare credentials and permissions are unchanged. Apply the chart RBAC along with the operator update.
4. During migration, old rc2 workers do not honor the Lease. Complete the operator rollout before assessing single-writer behavior. Do not restart cloudflared, Traefik or application workloads. Avoid concurrent operator installations for the same tunnel using different ownership namespaces/names.
5. Confirm exactly one Lease holder and one replica logging leadership-acquired. Confirm the second replica serves its webhook without issuing Cloudflare mutation requests. Check lease renewal and failover in staging.
6. Observe at least five minutes after the Cloudflare cooldown expires. Status-only Modified events must not initiate reconciliation, identical failures must not advance resourceVersion, and lastTransitionTime must remain stable for unchanged condition Status.
7. Verify all 22 hostnames recover their conditions. Change a staging hostname spec and namespace/ingress dependency, and verify convergence. Verify deletion remains blocked by the configured zero deletion limits and unmanaged routes remain intact.
8. Sample existing sites for expected HTTP responses and inspect Cloudflare request logs. Route inventory reads should track batched/full passes rather than hostname count. Security-policy inventory requests remain per requested policy and share the rate-limit gate.
9. Promote the validated immutable RC using SOURCE_IMAGE_TAG. Record the resulting digest, chart version, CI result and observed request counts. Publication alone does not update production Helm/Flux configuration.

## Limits to verify operationally

Kubernetes Lease election coordinates replicas using the same lease within one cluster. It does not provide Cloudflare-side fencing across clusters or independent installations. A network-partitioned request already accepted by Cloudflare cannot be recalled. Cooldown is shared in the active process and resets on process replacement; Retry-After is honored again if a new leader receives 429. The existing dependency polling interval still determines detection latency for namespace and ingress-only changes.
